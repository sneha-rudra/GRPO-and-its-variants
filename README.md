# Decoding LLM Alignment: A Concise Guide for  GRPO and its variants

Training & aligning Large Language & Vision Models with reinforcement learning has shifted dramatically. We have moved away from complex actor-critic setups towards  group normalized and sequence-level optimization algorithms. 

Whether you are designing an LLM post-training pipeline or scaling a reasoning model or preparing for an AI interview, keeping track of these advancements can be overwhelming. This concise guide breaks down the core reinforecement learning algorithms powering todays open & proprietary models. We will cover 6 methods - PPO, RLOO, GRPO,  Pref-GRPO, GSPO & GDPO.


# 1. The Complete Comparison Table

During RL (Reinforcement Learning) training for LLMs, algorithms update the weights of the policy model - aka the LLM being aligned -- to favor outputs with higher advantage - which is a measure of how much better or worse a sampled completion is; compared to a baseline.

| Method | What problem is it solving? | How does it work? | When to use it? | Big Picture in the RL revolution |
|--------|---------------------------|-------------------|-----------------|----------------------------------|
| **PPO** 
Proximal Policy Optimization | Reliable (i.e stable training) policy optimization for RLHF | - Critic model outputs a value estimate for each token. Think of the value estimate as - is how good is the rest of completion likely to be if we continue from that token. <br><br> - Clipped policy gradients.| - When you need token level precision <br><br> -Have the memory/ compute to afford a critic network <br><br> -Have human labelled preference pairs | The Classic Standard that RLHF uses.|
| **RLOO**
REINFORCE Leave-One-Out | Massive hardware overhead of keeping an extra critic in memory |  - Drops the critic <br><br> - Uses the average rewards of other completions in a group of rollout to get baseline | When you want to scale alignment | The Efficiency Pivot. Shifted the industry away from heavy critic setups |
| **GRPO** 
Group Relative Policy Optimization| High compute costs associated with training a model to reason through math & code | -Samples multiple completions for a given prompt  <br><br> - Computes advantage for each by subtracting the group's mean reward from the completion's reward| When training math/ coding models with automated verifiers | Unlocked the reasoning era -  core engine behind reasoning models like DeepSeek-R1 |
| **Pref-GRPO**
Preference GRPO | - Scaler rewards get games easily when rewards scores withn a group are near identical | Instead of raw scores, uses pair wise winrate within a group as reward signal | - When you want to align a model using a  preference pair data without a separate critic/ verifier model <br><br> - Alignment involves multiple subjective criteria | Incorporated human preference signals in GRPO  |
| **GSPO**
Group Sequence Policy Optimization | Noisy updates ie. high variance in gradients & training crashes while training MoEs for reasoning | Moves all the optimization math (ratios, clipping) to full sequence ie completion level instead of token level | For large scale model training eg MoEs | Enabled oong horizon reasoning for large sparse Mixture of Experts (MoE) models |
| **GDPO**
Group Reward Decoupled Policy Optimization| Reward  signal collapses when adding competing goals, washing out granular tradeoffs| Normalize each reward goal independently before adding| When you are balancing competing criteria eg accuracy, safety, brevity| Enabled multi-objective alignment under conflicting real world constraints |
